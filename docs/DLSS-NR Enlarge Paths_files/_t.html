DLSS-NR Enlarge Paths

What actually flows through the pipeline in each of the six Enlarge filter × Enlargement combinations, when the model runs below 100% resolution — and the one cell where the matched-residual gate turns itself off.

The spine every combination shares

The downscale and the model call are identical in all six cells. Nothing about the filter choice reaches them. What varies is one stage — and what the resolve is handed afterwards.

work resolution native resolution

Where the three filters diverge

Same two source buffers, same destination. The only difference is how many SGSR1 passes sit in between — and therefore what size the proxy is by the time the gate inspects it.

0 · Bilinear

No enlarge pass at all.

1 · SGSR1 (output only)

One pass, on the answer.

2 · SGSR1 (both)

Two passes. The proxy is enlarged too.

4 · SGSR1 (input only)not shipped

Inverts panel 1 — sharpen the real frame, leave the model's answer cheap.

The red pass in the third panel is the only structural difference between it and the second — and it is enough to change the gate's answer. Note the proxy is still derived from the downscaled copy in every panel; SGSR1 enlarges it, it does not replace it.

The fourth panel isn't a shipped option — DlssNrReducedUpscaleMethod only has values 0/1/2. It's drawn to make a point: the gate never looks at gModel at all, only gSource. Any configuration that enlarges the proxy trips it, regardless of what happens to the answer — sharpening the proxy alone is exactly as fatal to matched residual as sharpening both.

Why that third panel switches the feature off

The gate asks the bound proxy texture a question about itself: are you smaller than the frame? That was a valid proxy for "did the model run shrunk" right up until a pass was inserted that changes the answer.

The correct signal already exists: gModelWorkScale, computed in C++ before SGSR1 runs, added the same day for the neighbouring Replace detail-injection feature and never back-ported to this gate.

Replace mode collapses the table entirely

If the HDR mapping is set to a Replace reversible curve, the resolve overwrites its result with the decoded model answer and discards everything derived from the proxy — the residual block, the luminance ratio, the highlight guard, the colour blend.

The Enlargement control does nothing in any of the six rows above. Only the answer binding still reaches a pixel, so methods 1 and 2 become indistinguishable there while Bilinear still differs.

The shipped Optimized Defaults preset selects SGSR1 (both) and a Replace curve — so matched residual is switched off twice over, while the button's help text advertises it as on.
