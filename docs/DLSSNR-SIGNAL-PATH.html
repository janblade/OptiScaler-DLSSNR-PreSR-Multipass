Same ReversibleMode value the resolve stage reads later (stage 5) — the encode and resolve curves are always paired.

Pre-model resize

Only runs when reduced (a rounded-size check, not the raw scale) says the model's working resolution actually differs from native.

Note the asymmetry: above 100% the proxy is enlarged before the model sees it (a real upscale, so the model works from clean super-native input); below 100% it's minified with a plain box filter — there's no equivalent sharpening concern shrinking down.

Intermediate passes are clamped back into the proxy's valid range before feeding the next pass — a raw NGX answer isn't guaranteed to stay in [0,1], and that can't compound across passes unnoticed.

4

Post-model enlarge / shrink

Mirrors stage 2 in reverse: the model's answer goes back to native size before the resolve compares it against the frame.

Today's fix Both dispatches have to succeed, not just the answer's. Enlarging only the answer while the proxy stays small was tried first — the resolve's model − proxy edit then compares a sharp enlarged answer against a soft small-basis proxy, and the mismatch nearly cancels the native detail back out (reported in-game as "the low-res image got combined with the final image"). proxyNative exists specifically so both sides of that subtraction share the same detail basis.
5

Resolve

DlssNrMode_Resolve — the one stage every path above feeds into. resolveProxy, resolveAnswer, and the untouched original become the on-screen pixel.

Nuance DlssNrTransfer = "Matched residual" rebuilds the proxy from original with the same encode curve — but it only fires when the proxy arriving here is still smaller than native (modelRanSmall). When stage 4's enlarge succeeded, resolveProxy is already native-sized and this branch is skipped entirely; it only matters in the fallback case.
Today's finding Composed masks stage 4's resolution ceiling; Replace can't. Composed's ratio/hue blend is anchored on the native-resolution original the whole time, so it stays sharp even when the model+enlarge pipeline underneath is a little soft. Replace mode has nothing else to lean on — its output is entirely the model's answer at its working resolution, run through stage 4's enlarge. Below 100% model resolution, that's a real ceiling no upscale filter (SGSR1 or otherwise) can lift, because the detail was never in the model's answer to begin with.
