# Experimental residual across RR

On D3D12, enable **Apply before Super Resolution** and **Carry the pre-SR edit across RR** while the game uses Ray Reconstruction. Both new settings default off/unchanged. Native Vulkan has no host integration for this option.

NR resolves to a private render-resolution texture. A separate shader accumulates the signed difference from the original input, reprojecting with the game's active motion-vector rectangle and scale. Before the blend, the reprojected history is clamped to mean +/- 1.5*sigma of the current delta's own 3x3 (here 1D, since the accumulator is a plain row-major buffer) neighbourhood -- a TAA-style neighbourhood clamp that collapses reprojection smear at a motion boundary and, because it also pulls a zero/invalid history into range, fills disocclusions without the slow crawl. It is what lets the blend rate stay low without trailing on fast camera motion.

After the same RR evaluation succeeds, the accumulated layer is upscaled by a private NVIDIA DLSS SR feature -- fed the game's own real depth and motion vectors, so the carried edit gets genuine neural reconstruction at output resolution instead of a blur of a render-resolution layer -- and the shared detail strength is applied once. This is its own minimal NGX SuperSampling feature, independent of `DlssNr_DeferredSr` (that path stays unconditionally cancelled while RR is active) and respecting the same one-submission creation delay every NGX feature in this file needs. NVIDIA DLSS SR runtime unavailability, private creation failure, or private evaluation failure all fall back to a plain bilinear sample of the render-resolution history at output UV -- never a worse or broken picture, just less detailed. The game's RR colour input is left untouched. Hold frame, Compare, Debug view and Show skin mask must be disabled for this mode -- a debug view in particular writes its visualization into the same internal scratch the pre-pass resolves to, which would otherwise be fed to the accumulator as if it were the real edit.

Only a successful pre-pass can arm the post-pass; command list, parameter block and output must match. A skipped/failed/new pre-pass invalidates the previous result. Carrier textures start in their actual resource state, and the composition texture tracks the output's allocation dimensions and format independently of the input. Missing resources/PSO, failed dispatch, unsupported output layout or zero strength do not copy an invalid result onto the RR output. The post-pass restores the game's root/descriptor state.

Cold history and cuts fade in at the configured blend rate (default 0.08), snapped into the clamp's local band rather than crawling in over many frames. This is an experimental temporal average: view-dependent detail can smear and fast motion can lag. There is no depth-based disocclusion test, so motion validity alone does not establish that a surface is unchanged. It is not a claim of superior quality to post-RR NR.

Validation: Release x64 build; the committed residual CSO executed through Windows WARP for cold/warm history, the neighbourhood clamp, signed values, active MV offsets, invalid motion, render-to-output sampling, alpha and zero strength; CPU seam tests cover missing, mismatched, skipped and duplicate consumption. Both residual shader blobs/headers are regenerated from the source; the existing main NR shader is unchanged. The committed DX12 residual CSO is compiled with fxc (SM5.0 DXBC), not dxc, specifically so the same binary loads through both the real D3D12 pipeline and this WARP-executed D3D11 smoke test. No new gameplay quality or physical RTX 20/30 validation is claimed.
